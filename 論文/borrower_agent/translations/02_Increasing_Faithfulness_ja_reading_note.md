# Increasing Faithfulness 日本語読解ノート

PDF: [02_Increasing_Faithfulness_2021.acl-long.58.pdf](../pdfs/02_Increasing_Faithfulness_2021.acl-long.58.pdf)  
原題: Increasing Faithfulness in Knowledge-Grounded Dialogue with Controllable Features  
著者: Hannah Rashkin et al. / ACL 2021

## 一言まとめ

知識接地対話で、応答の**客観性・根拠忠実性**を上げるために、  
「一人称を使わない」「証拠との語彙一致を高める」「NLIでentailされる」などの**評価指標をそのまま制御コードにして入力に足す**と、hallucination が減るという話。  
今回の「構造化プロンプト vs Baseline」では、**Borrower側の入力構造を変えることで、こうした“良いスタイル”を自然に誘導できるか**を見るイメージで引用できる。

## Abstract / 導入の要点

- タスク: 文書に基づく knowledge-grounded dialogue（例: Wizard of Wikipedia）。
- 課題: 学習データには
  - 証拠文書に忠実な情報
  - 主観・雑談・一人称トーク
  が混ざっているので、そのまま学習すると「雑談スタイル」も覚えてしまい hallucination が増える。
- 提案:
  - 応答について3つの指標を自動で測る:
    - **Objective voice**: 一人称（I, my,..）がないか。
    - **Lexical Precision**: 応答の語がどれだけ evidence に含まれているか。
    - **NLI-based Entailment**: 応答が evidence に含まれる内容に含意されているか。
  - これらをカテゴリ化し、**制御コードトークン（<no-first-person>, <high-prec>, <entailed> など）として入力の先頭に付ける**。
  - さらに、生成時に「制約を満たすまで再サンプリングする」手法も検討。
- 結果:
  - 制御コードを入れるだけで、**人手評価の faithfulness / objectivity が有意に向上**。
  - relevance は多少下がるケースもあるが、hallucination 抑制には有効。

## Abstract 日本語訳（意訳）

知識接地対話では、応答が与えられたソース文書の証拠に基づく必要がある。しかし、そのような忠実さ（faithfulness）を制御しながら学習・生成することには難しさがある。既存データセットには、証拠に忠実な応答だけでなく、主観的な雑談・chit-chat 的な応答も混ざっている。そのため、応答が
（1）証拠に対してどれくらい情報的であるか
（2）どれくらい客観的であるか
を測って分離し、これらをトレーニング時の追加入力（制御）として使うことで、生成時に“より忠実な応答”を出す方向へモデルを誘導する。加えて、デコード時の resampling によって制御の効き方も検討する。自動評価に加え、人手評価では、提案した制御つき生成モデルがベースラインに比べて、より faithful で客観的だと判定されることを示す。

## 何が近いか（今回の実験設計との対応）

- **Baseline vs 制御付きモデルの比較**という構図が、そのまま
  - Baseline: 借り手記事全文を素で投げた Borrower LLM
  - 制御付き: 「目的・希望・制約・聞きたいこと」を構造化して渡す Borrower LLM
  という比較に対応する。
- Rashkin らは、**「モデルの入力の一部として“スタイル/制約”を明示する」→ Faithfulness が改善する**ことを示している。
  - 今回は「制御コードトークン」ではなく「構造化プロファイル（YAML→テキスト）」だが、**“明示的な構造/メタ情報を入力に足すと挙動が変わる”という同じ発想**。

## 今回への示唆（どう使うか）

- **評価観点の輸入**
  - Borrower 発話に対して、
    - 一人称乱用（不必要な主観）が少ないか
    - 借り手記事/プロフィールに存在しない事実をどれくらい足しているか（lexical precision 的な指標）
    - 記事との NLI 的 entailment
  を、人手 or LLM評価で測るときの参考指標にできる。
- **構造化プロンプトの仮説設定**
  - 構造化プロンプト条件では、
    - 「目的」「希望」「制約」などが明示されることで、Borrower LLM が**客観情報（条件・制約）にフォーカスしやすくなる**。
    - その結果、Rashkin らの制御コードモデルに近い、「高 lexical precision / entailed / 一人称少なめ」なスタイルになる、という仮説を立てられる。
- **実験の読み方**
  - Faithfulness 指標に加えて、簡単な proxy として「不要な一人称」「記事外の新規事実数」などもカウントし、  
    構造化プロンプト条件でそれらが減るかを見る、という補助分析ができる。

## 発表で使える一言

この論文は「評価指標（客観性・語彙一致・entailment）をそのまま制御コードとして入力に足すと、知識接地対話の忠実性が上がる」ことを示している。  
今回の研究では、制御コードの代わりに**借り手の目的・希望・制約を構造化して入力する**ことで、同様に「より忠実で目的指向な対話」を実現できるかを検証する。
