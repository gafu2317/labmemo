# Flow-of-Action: SOP Enhanced LLM Multi-Agent System for Root Cause Analysis

> raw: [[raw/papers/2502.08224.pdf]]

## 一行要約

標準作業手順書（SOP）フローを中心に5エージェントを協調させるマイクロサービス障害根本原因分析システムで、ReActベースライン35.50%から64.01%へ精度を向上。

## 問題設定

- クラウドマイクロサービスの障害Root Cause Analysis（RCA）は複雑な依存関係から困難
- LLMエージェントが知識なしに自律的に診断しようとすると非効率・不正確
- SOP（標準作業手順書）という専門知識をエージェントに体系的に組み込む必要

## アーキテクチャ: 5エージェント構成

| エージェント | 役割 |
|------------|------|
| MainAgent | タスク全体の調整・SOP選択 |
| ActionAgent | SOPステップの実行計画 |
| JudgeAgent | 実行結果の評価 |
| ObAgent | 観測データの収集・解析 |
| CodeAgent | 診断コードの生成・実行 |

## SOPフロー

```
match_sop → generate_sop → generate_sop_code → run_sop → match_observation
```

## 実験結果

| システム | 精度 |
|---------|------|
| ReAct (GPT-4-Turbo) | 35.50% |
| **Flow-of-Action (GPT-4-Turbo)** | **64.01%** |

## 我々の研究への示唆

直接的な関連度は低い（ITオペレーション特化）。ただし**SOP駆動マルチエージェント設計**のアーキテクチャパターンは、議論支援システムでの構造化された対話ファシリテーションエージェントの設計に応用可能。エージェントに手順書（=議論ルール・ファシリテーションプロトコル）を組み込む発想は参考になる。
