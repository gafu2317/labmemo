# 研究テーマ 候補案まとめ

---

## 案1：「議論の弱点の自動特定」

### 役立つ場面

議論・主張を書いた人が「どこが突かれやすいか」を事前に知りたい。
ディベート準備・小論文改善・研究発表準備など、**議論の壁打ち相手**として使える。

### 研究の必要性

GAQCorpusなどは議論「全体」の品質を測るが、「どの部分が最も脆弱か」をピンポイントで特定する研究がない。

### 新規性

議論の構成要素（前提・証拠・結論）のうち、どこが最も攻撃されやすいかを特定するタスクは未定義。

### 仮説

LLMは議論の最も脆弱な部分を、人間の専門家と一致した形で特定できる。

### 検証方法

既存の議論データセットに人手で「最も弱い点」ラベルを付け、LLMの判定と比較する。

### 深掘りポイント

- zero-shot / few-shot / Chain-of-Thought の条件比較
- 前提・証拠・結論のどの要素で間違えやすいか
- 人間専門家との一致率がどの議論タイプで下がるか

### 懸念点と対処

**懸念：チューニングなしのLLMで十分かもしれない**
→ 「十分かどうかを実証すること」自体が研究成果。
十分なら「LLMは壁打ち相手として使える」、不十分なら「どんな弱点を見逃すか」がわかる。どちらでも論文になる。

### 難易度

小規模アノテーション（人手ラベル付け）＋ API実験で完結。卒論として適切。

## 案2：「LLM生成反論の網羅性評価」

### 役立つ場面

壁打ちで複数の反論をもらったとき「まだ攻撃されていない角度がないか」を確認したい。
「5つ反論をもらったが全部同じ方向からの攻撃だった」を検出できる。

### 研究の必要性

反論生成研究は多いが、生成された反論セットが「どの角度をカバーしているか」を評価するフレームワークがない。

### 新規性

LLMが生成する複数の反論が特定の攻撃角度に偏るかを定量評価するタスクの定義と検証。

### 仮説

LLMが生成する複数の反論は、表面上は異なっても特定の攻撃角度（例：証拠の信頼性）に偏る。

### 検証方法

1. 攻撃角度の分類体系を定義（前提・証拠・論理的飛躍・結論・文脈など）
2. 人間評価者が「この議論に可能な攻撃角度」を網羅的に列挙 → ゴールドスタンダード
3. LLMにN個の反論を生成させ、各反論の攻撃角度を分類
4. カバレッジ率 = LLMが攻撃した角度数 / 人間が特定した全角度数 で評価

### 懸念点

**分類体系の妥当性をどう示すか**が設計上の最大の課題。
既存の議論モデル（Toulminモデル等）を参考に定義することで対処可能。

### 難易度

生成実験＋人手評価。分類体系の設計が必要だが、卒論の範囲で完結可能。

## 案3：「反論の攻撃ターゲットと説得効果の関係」

### 役立つ場面

ディベートで相手の議論を崩したいとき「前提を攻めるべきか、証拠を攻めるべきか、結論を直接攻めるべきか」という戦略を知りたい。

### 研究の必要性

反論の「生成」研究は多いが、「どこを攻めると人は実際に意見を変えるか」という戦略的問いに答えた研究がない。

### 新規性

反論の攻撃ターゲット（前提・証拠・結論）と実際の意見変化の関係を分析したタスクが未定義。

### 仮説

結論への直接攻撃より前提への攻撃の方が、実際の意見変化（CMVのdelta）を引き出しやすい。

### 検証方法

1. CMVのdelta付き・なし反論ペアを収集
2. 各反論の攻撃ターゲットをLLMで分類
3. 攻撃ターゲット別のdelta獲得率を統計的に比較

### 難易度

CMV（公開済み）＋LLM分類＋統計分析。アノテーション不要。

## 却下済み案（記録）

| 案 | 却下理由 |
|----|---------|
| 未解決論点の自動追跡 | 解決できることがない（研究の必要性がない） |
| 評価指標の比較 | すでに研究されていた（2503.05328） |
| スタンスのブレ検出 | 現代LLMでは問題が発生しない |
| 反論の内部一貫性 | コンテキストに入れれば解決、性能向上で意味を失う |
| 暗黙的結論の扱い | 何が解決されるのかが不明 |
| 反論の構造的差異 | 「少し違いました、終わり」で弱い結論にしかならない |
| 複数反論候補からの最良選択 | LLM性能テストどまりで、結果が誰かの行動を直接助けない |
