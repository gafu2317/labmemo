# V3 人手評価ルーブリック案

## 1. 評価単位

1つの大家―借り手対話全文を評価する。評価者には `method`、`information_level`、Planner、話法監査を見せない。ケース名から条件が推測される場合は匿名IDへ置換する。

12条件すべての総当たり比較は行わず、まず各対話を7件法で独立評価する。その後、同一ケース・同一情報条件内で話法を比較する。

## 2. 対話効果

各項目を1（まったくそう思わない）〜7（非常にそう思う）で評価する。

### Perceived Passion

- この借り手にとって、活動は重要なものだと感じる
- この借り手は、活動を今後も続けようとしていると感じる
- 借り手の思い入れが伝わる

### Meeting Intention

- この借り手本人から、さらに話を聞いてみたい
- この借り手を、貸す候補の一人として検討したい

### Authenticity / Enacted Commitment

- 発話は、この借り手本人に固有の内容だと感じる
- 熱意が言葉だけでなく、経験や行動を伴っていると感じる

### Dialogue Quality

- 大家の質問や懸念に直接答えている
- 大家との会話として自然である
- 情報量と発話の長さが適切である

### Over-persuasion

- 実際の記事内容以上に、借り手を良く見せようとしていると感じる
- 押しつけがましい、または売り込みが強すぎると感じる

## 3. 根拠忠実性

記事を参照できる研究者または別の評価者が判定する。

- 記事にない具体的事実がある
- 記事にない成果・周囲の評価がある
- 別々の記事事実を、記事にない因果関係で結びつけている
- 記事にない能力・対策・実行可能性を主張している
- 記事情報が少ないことを、もっともらしい一般知識で補っている

各項目を `なし / 軽微 / 明確` で記録し、該当箇所を抜き出す。

## 4. 操作チェック

自動の `method_audit` はスクリーニングに使い、主要なログは人手でも確認する。

- 構成要素が現れているか
- 構成要素が所定の順序か
- 欠落要素を創作していないか
- 話法を適用しなかった判断は妥当か
- 利用可能要素の実現（`available_slots_realized`）と必須要素を含む完全成立（`canonical_method_complete`）を混同していないか

## 5. 解釈上の注意

- 再現不成立の対話と、正しく再現したが低評価の対話を分ける
- Smallで面談意向だけが高くても、Faithfulnessや過剰説得が悪化していないか確認する
- AIDAはActionを制限した適応版であり、一般的なAIDA全体の効果へ一般化しない
- 現行実装では手法ごとに選ばれる証拠が異なり得るため、効果を語順だけに帰属しない
